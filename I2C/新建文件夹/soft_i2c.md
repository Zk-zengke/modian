# 软 I2C 说明文档

## 1. 什么是软 I2C

软 I2C，也叫软件模拟 I2C，是指不使用 MCU 内部的硬件 I2C 外设，而是通过普通 GPIO 引脚手动模拟 I2C 总线时序。

I2C 总线通常由两根线组成：

- `SCL`：时钟线，由主机控制时钟节拍。
- `SDA`：数据线，用于主机和从机之间传输数据。

在硬件 I2C 中，起始信号、停止信号、应答、数据移位、时钟控制等通常由外设自动完成；在软 I2C 中，这些动作需要程序通过 GPIO 的高低电平和输入输出方向切换来完成。

## 2. 为什么使用软 I2C

软 I2C 常见于以下场景：

- MCU 的硬件 I2C 引脚已经被占用。
- 项目需要在任意 GPIO 上连接 I2C 器件。
- 硬件 I2C 外设兼容性不好，需要手动控制时序。
- 需要调试特殊 I2C 器件，或者实现非标准时序。
- 一个芯片需要模拟多路 I2C 总线。

软 I2C 的优点是灵活，缺点是占用 CPU 时间，速度和稳定性通常不如硬件 I2C。

## 3. I2C 总线基本特性

I2C 是一种同步、半双工、主从结构的串行通信总线。

典型特性如下：

- 总线上可以有一个或多个主机，也可以有多个从机。
- 每个从机有自己的地址。
- 数据按字节传输，高位先传。
- 每传输 8 位数据后，接收方需要返回 1 位应答信号。
- 总线空闲时，`SCL` 和 `SDA` 都保持高电平。
- I2C 引脚通常采用开漏或开集电极结构，需要外部上拉电阻。

## 4. 开漏输出和上拉电阻

I2C 总线不能像普通 GPIO 那样主动输出高电平。标准 I2C 设备一般只能主动拉低总线，不能主动拉高总线。

因此，总线高电平依赖上拉电阻：

- 设备输出低电平：主动把线拉到 `GND`。
- 设备释放总线：引脚变成高阻态，由上拉电阻把线拉到高电平。

软 I2C 实现时通常有两种方式：

1. GPIO 支持开漏输出  
   输出 `0` 表示拉低总线，输出 `1` 表示释放总线。

2. GPIO 不使用开漏模式  
   输出低电平时设置为输出模式并写 `0`，释放总线时设置为输入模式。

第二种方式更接近 I2C 的真实总线行为，兼容性也更好。

## 5. I2C 关键时序

### 5.1 空闲状态

总线空闲时：

```text
SCL = 1
SDA = 1
```

### 5.2 起始信号 START

当 `SCL` 为高电平时，`SDA` 从高电平变为低电平，表示起始信号。

```text
SCL: 1
SDA: 1 -> 0
```

### 5.3 停止信号 STOP

当 `SCL` 为高电平时，`SDA` 从低电平变为高电平，表示停止信号。

```text
SCL: 1
SDA: 0 -> 1
```

### 5.4 数据有效条件

I2C 数据线的变化必须发生在 `SCL` 低电平期间。

当 `SCL` 为高电平时，`SDA` 上的数据必须保持稳定，因为接收方通常会在 `SCL` 高电平期间采样数据。

```text
SCL 低电平：允许改变 SDA
SCL 高电平：读取或保持 SDA
```

### 5.5 应答 ACK 和非应答 NACK

每传输 8 位数据后，第 9 个时钟周期用于应答。

- `ACK`：接收方拉低 `SDA`，表示成功接收。
- `NACK`：接收方释放 `SDA`，`SDA` 保持高电平，表示不再接收或接收失败。

主机写数据时，由从机返回 ACK。

主机读数据时，主机需要在每个字节后返回 ACK 或 NACK：

- 还要继续读：主机返回 ACK。
- 最后一个字节：主机返回 NACK，然后发送 STOP。

## 6. 软 I2C 基本函数

一个完整的软 I2C 驱动通常包含以下基础函数：

- `I2C_Delay()`：产生短延时，控制通信速度。
- `SCL_H()`：释放或拉高 SCL。
- `SCL_L()`：拉低 SCL。
- `SDA_H()`：释放 SDA。
- `SDA_L()`：拉低 SDA。
- `SDA_Read()`：读取 SDA 电平。
- `I2C_Start()`：发送起始信号。
- `I2C_Stop()`：发送停止信号。
- `I2C_WriteByte()`：发送 1 字节。
- `I2C_ReadByte()`：读取 1 字节。
- `I2C_WaitAck()`：等待应答。
- `I2C_SendAck()`：发送 ACK。
- `I2C_SendNack()`：发送 NACK。

## 7. 典型实现流程

### 7.1 发送起始信号

```c
void I2C_Start(void)
{
    SDA_H();
    SCL_H();
    I2C_Delay();

    SDA_L();
    I2C_Delay();

    SCL_L();
    I2C_Delay();
}
```

流程说明：

1. 先释放 `SDA` 和 `SCL`，确保总线处于空闲状态。
2. 在 `SCL` 高电平期间，把 `SDA` 从高拉低。
3. 拉低 `SCL`，准备后续数据传输。

### 7.2 发送停止信号

```c
void I2C_Stop(void)
{
    SDA_L();
    SCL_H();
    I2C_Delay();

    SDA_H();
    I2C_Delay();
}
```

流程说明：

1. 先确保 `SDA` 为低。
2. 释放 `SCL`，让 `SCL` 变高。
3. 在 `SCL` 高电平期间释放 `SDA`，形成停止信号。

### 7.3 发送 1 位数据

```c
void I2C_WriteBit(uint8_t bit)
{
    SCL_L();

    if (bit) {
        SDA_H();
    } else {
        SDA_L();
    }

    I2C_Delay();
    SCL_H();
    I2C_Delay();
    SCL_L();
    I2C_Delay();
}
```

核心点：

- 在 `SCL` 低电平时设置 `SDA`。
- 在 `SCL` 高电平时让对方采样。

### 7.4 读取 1 位数据

```c
uint8_t I2C_ReadBit(void)
{
    uint8_t bit;

    SCL_L();
    SDA_H();        // 释放 SDA，让从机控制数据线
    I2C_Delay();

    SCL_H();
    I2C_Delay();
    bit = SDA_Read();

    SCL_L();
    I2C_Delay();

    return bit;
}
```

读取时主机必须释放 `SDA`，否则主机会和从机同时驱动数据线，可能导致通信失败，严重时甚至损坏 IO。

### 7.5 发送 1 字节

```c
void I2C_WriteByte(uint8_t data)
{
    for (int i = 0; i < 8; i++) {
        I2C_WriteBit(data & 0x80);
        data <<= 1;
    }
}
```

I2C 规定高位先传，所以先发送 `bit7`，最后发送 `bit0`。

### 7.6 读取 1 字节

```c
uint8_t I2C_ReadByte(void)
{
    uint8_t data = 0;

    for (int i = 0; i < 8; i++) {
        data <<= 1;
        data |= I2C_ReadBit();
    }

    return data;
}
```

### 7.7 等待 ACK

```c
uint8_t I2C_WaitAck(void)
{
    uint8_t ack;

    SCL_L();
    SDA_H();        // 释放 SDA，等待从机拉低
    I2C_Delay();

    SCL_H();
    I2C_Delay();

    ack = SDA_Read();

    SCL_L();
    I2C_Delay();

    return ack == 0;    // 返回 1 表示收到 ACK
}
```

这里读取到 `0` 表示 ACK，读取到 `1` 表示 NACK。

### 7.8 主机发送 ACK 和 NACK

```c
void I2C_SendAck(void)
{
    I2C_WriteBit(0);
}

void I2C_SendNack(void)
{
    I2C_WriteBit(1);
}
```

## 8. 典型写寄存器流程

很多 I2C 传感器、EEPROM、RTC 芯片都采用寄存器访问方式。写寄存器的一般流程如下：

```text
START
发送设备地址 + 写位
等待 ACK
发送寄存器地址
等待 ACK
发送数据
等待 ACK
STOP
```

示例：

```c
uint8_t I2C_WriteReg(uint8_t dev_addr, uint8_t reg_addr, uint8_t data)
{
    I2C_Start();

    I2C_WriteByte((dev_addr << 1) | 0);
    if (!I2C_WaitAck()) {
        I2C_Stop();
        return 0;
    }

    I2C_WriteByte(reg_addr);
    if (!I2C_WaitAck()) {
        I2C_Stop();
        return 0;
    }

    I2C_WriteByte(data);
    if (!I2C_WaitAck()) {
        I2C_Stop();
        return 0;
    }

    I2C_Stop();
    return 1;
}
```

注意：这里的 `dev_addr` 通常指 7 位地址，真正发送时需要左移 1 位，并在最低位加入读写位。

## 9. 典型读寄存器流程

读寄存器通常需要先写入目标寄存器地址，再重新发送起始信号进行读取。

```text
START
发送设备地址 + 写位
等待 ACK
发送寄存器地址
等待 ACK

RESTART
发送设备地址 + 读位
等待 ACK
读取数据
主机发送 NACK
STOP
```

示例：

```c
uint8_t I2C_ReadReg(uint8_t dev_addr, uint8_t reg_addr, uint8_t *data)
{
    I2C_Start();

    I2C_WriteByte((dev_addr << 1) | 0);
    if (!I2C_WaitAck()) {
        I2C_Stop();
        return 0;
    }

    I2C_WriteByte(reg_addr);
    if (!I2C_WaitAck()) {
        I2C_Stop();
        return 0;
    }

    I2C_Start();    // repeated start

    I2C_WriteByte((dev_addr << 1) | 1);
    if (!I2C_WaitAck()) {
        I2C_Stop();
        return 0;
    }

    *data = I2C_ReadByte();
    I2C_SendNack();
    I2C_Stop();

    return 1;
}
```

## 10. 软 I2C 的速度控制

软 I2C 的速度主要由 `I2C_Delay()` 决定。延时越短，通信速度越快；延时越长，通信越慢但越稳定。

常见 I2C 速率：

- 标准模式：100 kHz
- 快速模式：400 kHz
- 高速模式：3.4 MHz

软 I2C 通常更适合 100 kHz 或更低速度。对于普通传感器和配置类器件，几十 kHz 到 100 kHz 已经足够。

实际项目中，不建议一开始就追求高速。应先使用较长延时保证通信成功，再逐步缩短延时。

## 11. 上拉电阻选择

常见上拉电阻范围：

- `10 kΩ`：速度较低、总线较短、设备较少时常用。
- `4.7 kΩ`：100 kHz 场景常见。
- `2.2 kΩ`：总线电容较大或速度较高时可能使用。

上拉电阻过大，会导致上升沿太慢，通信容易失败。

上拉电阻过小，会增加低电平电流，导致功耗变大，也可能超过器件拉低能力。

实际选择需要结合：

- 总线电压
- 总线长度
- 连接设备数量
- 目标通信速度
- PCB 走线电容

## 12. 常见问题

### 12.1 没有 ACK

可能原因：

- 设备地址错误，尤其是 7 位地址和 8 位地址混淆。
- `SDA` 没有正确释放，导致从机无法拉低应答。
- 上拉电阻缺失或阻值不合适。
- 从机没有供电，或者电平不匹配。
- `SCL` 和 `SDA` 接反。
- 时序太快，从机来不及响应。
- 从机处于忙状态，例如 EEPROM 正在内部写入。

### 12.2 总线一直为低

可能原因：

- 某个设备正在拉低 `SDA` 或 `SCL`。
- MCU GPIO 配置错误，一直输出低电平。
- 总线短路到地。
- 上一次通信异常中断，从机状态机卡住。

处理方法：

- 检查 GPIO 模式和电平。
- 断开从机逐个排查。
- 主机尝试发送多个 `SCL` 脉冲释放总线。
- 最后发送 STOP 信号恢复空闲状态。

### 12.3 读到的数据全是 `0xFF`

可能原因：

- 从机没有响应，`SDA` 一直被上拉为高。
- 设备地址错误。
- 寄存器地址错误。
- 读流程缺少 repeated start。
- 主机读取前没有释放 `SDA`。

### 12.4 读到的数据全是 `0x00`

可能原因：

- `SDA` 被拉低。
- GPIO 输入读取函数异常。
- 主机仍然把 `SDA` 配置为输出低电平。
- 从机异常或总线短路。

## 13. 调试建议

调试软 I2C 时，逻辑分析仪非常有用。建议重点观察：

- 起始信号和停止信号是否正确。
- `SCL` 高电平期间 `SDA` 是否稳定。
- 每个字节后第 9 个时钟是否有 ACK。
- 设备地址是否正确。
- 读操作是否有 repeated start。
- 主机读数据前是否释放了 `SDA`。
- 波形上升沿是否过慢。

如果没有逻辑分析仪，也可以先降低通信速度，并用示波器或 LED 简单确认引脚是否有变化。

## 14. 软 I2C 和硬件 I2C 对比

| 项目 | 软 I2C | 硬件 I2C |
| --- | --- | --- |
| 引脚选择 | 灵活，几乎任意 GPIO | 通常固定或有限复用 |
| CPU 占用 | 较高 | 较低 |
| 速度 | 通常较低 | 可支持更高速度 |
| 稳定性 | 依赖软件时序 | 由硬件外设保证 |
| 实现复杂度 | 需要自己写时序 | 使用外设寄存器或库 |
| 调试灵活性 | 高 | 较低 |

## 15. 使用软 I2C 的注意事项

- `SDA` 和 `SCL` 必须有上拉能力。
- 释放总线时不要主动输出高电平，优先使用开漏或输入模式。
- 数据变化应发生在 `SCL` 低电平期间。
- 读取数据前必须释放 `SDA`。
- 每发送 1 字节后必须处理 ACK。
- 读最后一个字节后应发送 NACK。
- 通信异常时要及时发送 STOP。
- 速度先慢后快，确认稳定后再优化。
- 多任务或中断环境下要注意时序被打断的问题。

## 16. 总结

软 I2C 的本质是用 GPIO 模拟 I2C 总线的电平变化。只要掌握以下几个关键点，就能实现一个可靠的软 I2C 驱动：

- 总线空闲时 `SCL` 和 `SDA` 都为高。
- `SCL` 高电平期间 `SDA` 从高到低是 START。
- `SCL` 高电平期间 `SDA` 从低到高是 STOP。
- 数据在 `SCL` 低电平期间改变，在 `SCL` 高电平期间采样。
- 每 8 位数据之后都有 1 位 ACK/NACK。
- I2C 是开漏总线，释放总线比主动拉高更重要。

软 I2C 不适合追求极限速度，但非常适合教学、调试、低速传感器通信和引脚资源紧张的项目。
