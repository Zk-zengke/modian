# 02 I2C 地址与 SDA/SCL 时序

## 1. 先分清 7 位地址和 8 位地址字节

I2C 标准里，常用地址是 **7 位地址**。

总线上真正先发送的第一个字节不是单纯的地址，而是：

```text
7 位从机地址 + 1 位 R/W
```

结构如下：

```text
bit7 bit6 bit5 bit4 bit3 bit2 bit1 bit0
 A6   A5   A4   A3   A2   A1   A0   R/W
```

其中：

- `A6~A0`：7 位从机地址
- `R/W = 0`：写
- `R/W = 1`：读

所以所谓的“8 位地址”，严格来说应该叫 **地址控制字节** 或 **地址 + 读写位**。

## 2. 为什么不是 8 位地址

I2C 普通寻址模式本来就是 7 位地址，不是 8 位地址。

也就是说，并不是“8 位地址少了一位拿去做 R/W”，而是协议一开始就规定：

```text
地址字段：7 位
方向字段：1 位
```

这 8 位组合起来，构成总线上发送的第一个字节。

因此不会出现“地址不全”的问题。

## 3. 7 位地址和 8 位地址字节的换算

如果知道 7 位地址：

```text
写地址字节 = 7 位地址 << 1 | 0
读地址字节 = 7 位地址 << 1 | 1
```

例如 7 位地址是 `0x3C`：

```text
0x3C = 0b0111100
```

写操作：

```text
0111100 0 = 0b01111000 = 0x78
```

读操作：

```text
0111100 1 = 0b01111001 = 0x79
```

所以：

```text
7 位地址：0x3C
写地址字节：0x78
读地址字节：0x79
```

这三个值描述的是同一个 I2C 从机，只是写法不同。

## 4. 为什么很多资料写 OLED 地址是 0x78

很多 OLED 模块资料会写：

```text
I2C address: 0x78
```

但这里的 `0x78` 往往不是标准 7 位地址，而是 **8 位写地址字节**。

把 `0x78` 拆开：

```text
0x78 = 0b01111000
```

也就是：

```text
0111100 0
```

其中：

```text
0111100 = 0x3C，这是 7 位从机地址
0 = 写操作
```

因此：

```text
0x78 是写地址字节
0x79 是读地址字节
0x3C 才是标准 7 位地址
```

## 5. 例子一：向从机 0x78 写两个字节

这里有两种理解。

### 情况 A：0x78 是 7 位地址

如果 `0x78` 是 7 位从机地址，那么写地址字节是：

```text
0x78 << 1 | 0 = 0xF0
```

写两个字节的完整过程：

```text
START
发送 0xF0
从机 ACK
发送 Byte1
从机 ACK
发送 Byte2
从机 ACK
STOP
```

简写为：

```text
S  0xF0  ACK  Byte1  ACK  Byte2  ACK  P
```

### 情况 B：0x78 是 8 位写地址字节

如果资料里说的 `0x78` 是 8 位写地址字节，那么真实 7 位地址是：

```text
0x78 >> 1 = 0x3C
```

这时写两个字节的过程就是：

```text
S  0x78  ACK  Byte1  ACK  Byte2  ACK  P
```

读同一个设备时，地址字节应该是：

```text
0x79
```

## 6. 例子二：从从机 0x20 读一个字节

同样有两种理解。

### 情况 A：0x20 是 7 位地址

如果 `0x20` 是 7 位从机地址，那么读地址字节是：

```text
0x20 << 1 | 1 = 0x41
```

读一个字节的完整过程：

```text
START
发送 0x41
从机 ACK
从机发送 Data
主机 NACK
STOP
```

简写为：

```text
S  0x41  ACK  Data  NACK  P
```

最后主机发送 `NACK`，是因为主机只想读 1 个字节，告诉从机“不继续读了”。

### 情况 B：0x20 是 8 位写地址字节

如果 `0x20` 是 8 位写地址字节，那么真实 7 位地址是：

```text
0x20 >> 1 = 0x10
```

同一个设备的读地址字节是：

```text
0x21
```

读一个字节的过程就是：

```text
S  0x21  ACK  Data  NACK  P
```

## 7. SDA 和 SCL 的基本规则

I2C 有两根线：

```text
SCL：Serial Clock，时钟线
SDA：Serial Data，数据线
```

基本规则：

- `SCL` 由主机产生。
- `SDA` 用来传输地址、数据、ACK 和 NACK。
- `SCL` 高电平期间，`SDA` 必须保持稳定。
- `SCL` 低电平期间，`SDA` 才允许变化。
- 接收方通常在 `SCL` 高电平时读取 `SDA`。

只有两个特殊情况例外：

```text
START：SCL 高电平时，SDA 从高变低
STOP： SCL 高电平时，SDA 从低变高
```

## 8. START 和 STOP

起始信号：

```text
SCL:  ________--------________
SDA:  --------\_______________
              START
```

含义：

```text
SCL 为高时，SDA 从高变低
```

停止信号：

```text
SCL:  ________--------________
SDA:  ________/---------------
              STOP
```

含义：

```text
SCL 为高时，SDA 从低变高
```

## 9. 发送 1 个字节时 SDA/SCL 怎么配合

以发送 `0x78` 为例：

```text
0x78 = 0b01111000
```

I2C 先发送最高位，所以 SDA 依次是：

```text
0 1 1 1 1 0 0 0
```

每一位都对应一个 SCL 脉冲：

```text
SCL:  _/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_/‾\_
SDA:   0   1   1   1   1   0   0   0
```

注意：

```text
SCL 低电平时，发送方改变 SDA
SCL 高电平时，接收方读取 SDA
```

## 10. ACK 和 NACK

每发送 8 位后，还要再给第 9 个 SCL 脉冲。

这个第 9 位用于 ACK 或 NACK。

```text
ACK  = SDA 被拉低，表示收到
NACK = SDA 保持高，表示不继续或无响应
```

写操作时：

```text
主机发送 8 位
主机释放 SDA
从机在第 9 个时钟拉低 SDA，表示 ACK
```

读操作时：

```text
从机发送 8 位
主机在第 9 个时钟给 ACK 或 NACK
```

如果主机还想继续读，就给 ACK。

如果主机不想继续读，就给 NACK。

读 1 个字节时，最后通常是：

```text
Data 后面接 NACK，然后 STOP
```

## 11. 写两个字节的 SCL 数量

写两个字节时，包含：

```text
地址字节 8 位 + ACK 1 位
数据字节 8 位 + ACK 1 位
数据字节 8 位 + ACK 1 位
```

一共：

```text
9 + 9 + 9 = 27 个 SCL 脉冲
```

START 和 STOP 是 SDA 在 SCL 高电平时的特殊变化，不算普通数据位。

## 12. 读一个字节的 SCL 数量

读一个字节时，包含：

```text
地址字节 8 位 + ACK 1 位
数据字节 8 位 + NACK 1 位
```

一共：

```text
9 + 9 = 18 个 SCL 脉冲
```

## 13. 总结

标准 I2C 地址是 7 位：

```text
7 位地址 + 1 位 R/W = 总线上发送的第一个字节
```

如果看到：

```text
0x78
```

它可能是：

- 7 位地址 `0x78`
- 8 位写地址字节 `0x78`

判断方法：

```text
如果资料同时写 0x78 写、0x79 读，那么真实 7 位地址是 0x3C。
如果资料写 7-bit address = 0x3C，那么写地址字节是 0x78，读地址字节是 0x79。
```

核心记忆：

```text
写：地址最低位是 0
读：地址最低位是 1
SCL 高电平时 SDA 稳定
SCL 低电平时 SDA 改变
START 和 STOP 是 SCL 高电平时 SDA 的特殊变化
每 8 位后面都有 1 位 ACK 或 NACK
```
