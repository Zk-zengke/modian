# 01 I2C 基础概念

## 1. I2C 是什么

I2C 是一种芯片之间通信的总线协议。

它的全称是 Inter-Integrated Circuit，意思是“集成电路之间的通信”。它主要用于同一块电路板上，让一个主控芯片和多个外设芯片进行通信。

常见场景：

- MCU 读取温湿度传感器。
- MCU 控制 OLED 显示屏。
- MCU 读取 EEPROM 存储器。
- MCU 配置 RTC 实时时钟芯片。
- 主控芯片和电源管理芯片通信。
- 主控芯片和触摸芯片、音频芯片、摄像头配置芯片通信。

一句话理解：

> I2C 是一种用两根线连接多个芯片，并让它们按地址通信的协议。

## 2. I2C 的两根线

I2C 最核心的两根信号线是：

```text
SCL：Serial Clock，串行时钟线
SDA：Serial Data，串行数据线
```

SCL 负责提供通信节奏。

SDA 负责传输数据。

典型连接方式：

```text
                SCL
MCU  --------------------------------  传感器
  |  --------------------------------  EEPROM
  |  --------------------------------  OLED
                SDA
```

更完整一点可以画成：

```text
          SCL -----------------------------------------
          SDA -----------------------------------------
            |             |              |            |
          MCU          传感器          EEPROM        OLED
         主机           从机            从机          从机
```

多个 I2C 设备可以共用同一组 SCL 和 SDA。

这就是 I2C 很重要的价值：它不需要给每个设备都单独准备一组通信线。

## 3. 主机和从机

I2C 通信里通常有两类角色：

```text
主机：Master，也可以叫 Controller
从机：Slave，也可以叫 Target
```

主机负责：

- 发起通信。
- 产生 SCL 时钟。
- 指定要访问哪个设备。
- 决定本次通信是读还是写。
- 结束通信。

从机负责：

- 等待主机访问。
- 判断地址是不是自己。
- 被选中后响应主机。
- 根据主机要求接收数据或发送数据。

常见情况下：

```text
MCU 是主机。
传感器、OLED、EEPROM、RTC 是从机。
```

例如：

```text
MCU：地址 0x68 的设备，请响应。
RTC：我是 0x68，我响应。

MCU：地址 0x3C 的设备，请响应。
OLED：我是 0x3C，我响应。
```

## 4. I2C 为什么需要地址

因为多个设备共用同一组 SCL/SDA，所以主机必须先说明自己要和谁通信。

这个“谁”就是 I2C 地址。

可以把 I2C 总线想象成一个班级：

```text
老师：3 号同学，请回答问题。
只有 3 号同学回答。

老师：7 号同学，请把作业交上来。
只有 7 号同学动作。
```

在 I2C 里：

```text
老师 = 主机
学生 = 从机
学号 = I2C 地址
公共教室 = I2C 总线
```

所以多个设备不会同时乱说话，因为主机每次通信前都会先发送目标地址。

## 5. 一个简单通信过程

以 MCU 读取温度传感器为例：

```text
1. MCU 发起通信。
2. MCU 发送温度传感器的地址。
3. 温度传感器发现地址是自己，于是响应。
4. MCU 告诉传感器：我要读取温度数据。
5. 传感器把温度数据通过 SDA 发给 MCU。
6. MCU 结束通信。
```

抽象成 I2C 行为：

```text
Start
发送设备地址
选择读或写
传输数据
Stop
```

现在不需要急着理解每一个时序细节。第一阶段只需要知道：I2C 通信一定是主机先发起，先找地址，再进行数据读写。

## 6. I2C 的作用

I2C 的核心作用是：

> 让主控芯片用很少的引脚，和多个外设芯片进行有序通信。

它主要解决三个问题。

第一，减少连线。

如果没有总线，MCU 连接多个外设可能需要很多线：

```text
MCU -> 设备 1：一组线
MCU -> 设备 2：一组线
MCU -> 设备 3：一组线
MCU -> 设备 4：一组线
```

使用 I2C 后：

```text
MCU -> 所有 I2C 设备：SCL + SDA
```

第二，节省引脚。

MCU 的引脚数量有限。I2C 只占用两根主要信号线，就可以扩展多个外设。

第三，统一通信规则。

不同芯片只要支持 I2C，就可以按照同一套规则通信：

```text
怎么开始
怎么发地址
怎么读
怎么写
怎么确认收到
怎么结束
```

## 7. I2C 适合做什么

I2C 适合：

- 低速或中低速通信。
- 同一块电路板上的短距离通信。
- 连接多个低速外设。
- 读写外设寄存器。
- 对引脚数量比较敏感的设计。

典型外设：

- 温湿度传感器。
- 气压传感器。
- 加速度计和陀螺仪。
- OLED 显示屏。
- EEPROM。
- RTC 实时时钟。
- ADC、DAC。
- IO 扩展芯片。
- 电源管理芯片。

I2C 不太适合：

- 很长距离通信。
- 很高速的大数据传输。
- 强干扰环境下的远距离连接。
- 大量连续图像数据传输。

这些场景可能会用 SPI、UART、CAN、以太网等其他通信方式。

## 8. I2C 和 SPI 的直观区别

SPI 通常更快，但线更多。

常见 SPI 线：

```text
SCLK：时钟
MOSI：主机发给从机
MISO：从机发给主机
CS：片选
```

多个 SPI 设备通常需要多个 CS：

```text
SCLK + MOSI + MISO + CS1 + CS2 + CS3 ...
```

I2C 通常只需要：

```text
SCL + SDA
```

所以可以先这样记：

```text
I2C：线少，适合低速多设备。
SPI：速度快，但通常占用更多线。
```

## 9. 第一阶段必须记住的知识点

这一阶段先记住这些就够了：

- I2C 是芯片之间通信的协议。
- I2C 常用于 MCU 和板上外设通信。
- I2C 主要使用两根线：SCL 和 SDA。
- SCL 是时钟线。
- SDA 是数据线。
- 主机负责发起通信和产生时钟。
- 从机根据地址响应主机。
- 多个 I2C 从机可以共用同一组 SCL/SDA。
- 地址用来区分总线上的不同设备。
- I2C 的优势是省线、省引脚、规则统一。
