# I2C 学习路线

## 0. 学习目标

学完 I2C 后，你应该能够做到：

- 看懂 I2C 的基本连接方式：SCL、SDA、上拉电阻、主机、从机。
- 理解 I2C 的通信过程：起始信号、地址、读写位、ACK/NACK、数据、停止信号。
- 能用 MCU 或开发板读取一个 I2C 传感器。
- 能根据芯片手册写出简单的 I2C 读写寄存器代码。
- 能用逻辑分析仪或示波器分析 I2C 波形。
- 能定位常见问题：无 ACK、地址错误、上拉不合适、总线被拉低、时序异常。

## 1. 第一阶段：建立整体概念

重点问题：

- I2C 是什么？
- I2C 用来解决什么问题？
- 为什么 I2C 只需要两根线？
- 什么是主机和从机？
- 什么是设备地址？

需要掌握：

- SCL 是时钟线。
- SDA 是数据线。
- 主机负责发起通信和产生时钟。
- 从机根据地址响应主机。
- 多个 I2C 设备可以共享同一组 SCL/SDA。
- I2C 适合板内、短距离、低到中速通信。

建议练习：

- 画出一个 MCU 连接 OLED、温度传感器、EEPROM 的 I2C 总线图。
- 找 3 个常见 I2C 器件，记录它们的 I2C 地址。

## 2. 第二阶段：理解硬件连接

重点问题：

- 为什么 I2C 需要上拉电阻？
- 什么是开漏输出？
- SCL/SDA 空闲时为什么是高电平？
- 上拉电阻太大或太小会有什么影响？
- I2C 总线可以接多长？

需要掌握：

- I2C 的 SDA 和 SCL 通常是开漏或开集电极结构。
- 设备只能主动把线拉低，不能主动输出高电平。
- 高电平依靠上拉电阻拉上去。
- 总线空闲时，SCL 和 SDA 都应为高电平。
- 常见上拉电阻范围通常是 2.2k 到 10k，具体要结合电压、速率和总线电容。

建议练习：

- 在原理图中找到 I2C 的上拉电阻。
- 用万用表测量 SCL/SDA 空闲电平。
- 对比 100 kHz 和 400 kHz 下上拉电阻对波形上升沿的影响。

## 3. 第三阶段：掌握 I2C 基本时序

重点问题：

- 起始信号是什么？
- 停止信号是什么？
- 数据什么时候有效？
- ACK 和 NACK 是什么？
- 地址帧由哪些部分组成？

需要掌握：

- 起始信号：SCL 为高电平时，SDA 从高变低。
- 停止信号：SCL 为高电平时，SDA 从低变高。
- 数据传输时，SDA 在 SCL 低电平期间变化。
- 数据采样时，SDA 在 SCL 高电平期间保持稳定。
- 每传输 8 bit 数据后，会有 1 bit ACK/NACK。
- 7 位地址加 1 位读写位组成地址帧。

典型写操作：

```text
Start
从机地址 + Write
ACK
寄存器地址
ACK
写入数据
ACK
Stop
```

典型读操作：

```text
Start
从机地址 + Write
ACK
寄存器地址
ACK
Repeated Start
从机地址 + Read
ACK
读取数据
NACK
Stop
```

建议练习：

- 手动画出一次 I2C 写寄存器的时序。
- 手动画出一次 I2C 读寄存器的时序。
- 用逻辑分析仪抓一次 I2C 波形，并标出 Start、Address、ACK、Data、Stop。

## 4. 第四阶段：学习地址和读写方向

重点问题：

- 什么是 7 位地址？
- 什么是 8 位地址写法？
- 为什么有些手册写 0x68，有些代码写 0xD0？
- 读写位在哪里？
 
需要掌握：

- I2C 常用 7 位地址。
- 地址帧最低位是读写位。
- 读写位为 0 表示写。
- 读写位为 1 表示读。
- 有些资料把 7 位地址左移一位后写成 8 位地址，容易造成混淆。

例子：

```text
7 位地址：0x68
写地址帧：0xD0，即 0x68 << 1 | 0
读地址帧：0xD1，即 0x68 << 1 | 1
```

建议练习：

- 找一个 I2C 器件的数据手册，确认它使用的是 7 位地址还是 8 位地址描述。
- 用 I2C 扫描程序扫描总线上的设备地址。

## 5. 第五阶段：读懂 I2C 外设寄存器

重点问题：

- 什么是寄存器地址？
- 为什么读数据前通常要先写寄存器地址？
- 连续读取和单字节读取有什么区别？
- 多字节数据如何组合？

需要掌握：

- 很多 I2C 外设内部都有寄存器表。
- 主机通过写寄存器地址选择要访问的位置。
- 读取传感器数据时，经常需要连续读多个寄存器。
- 多字节数据可能是大端或小端，需要看数据手册。
- 有符号数据、补码、比例系数都要根据手册换算。

建议练习：

- 选择一个传感器，比如 AHT20、SHT30、BMP280、MPU6050。
- 找到它的数据寄存器。
- 写出“读设备 ID”或“读温度数据”的步骤。

## 6. 第六阶段：写代码实践

推荐顺序：

1. 先用开发板自带库读一个 I2C 设备。
2. 再封装 `i2c_read_register` 和 `i2c_write_register`。
3. 再尝试不用高级驱动，只按数据手册写初始化和读取流程。
4. 最后再学习软件模拟 I2C。

建议实验：

- I2C 扫描器：扫描总线上的设备地址。
- 读取设备 ID：确认通信正常。
- 读取传感器数据：完成一次真实应用。
- 配置寄存器：修改采样率、量程、工作模式等参数。
- 连续读取多个字节：理解寄存器自动递增。

推荐代码接口：

```c
int i2c_write_register(uint8_t dev_addr, uint8_t reg_addr, uint8_t data);
int i2c_read_register(uint8_t dev_addr, uint8_t reg_addr, uint8_t *data);
int i2c_read_registers(uint8_t dev_addr, uint8_t reg_addr, uint8_t *buf, uint16_t len);
```

## 7. 第七阶段：学习排错方法

常见问题：

- 扫描不到设备。
- 设备没有 ACK。
- 读到的数据全是 0x00 或 0xFF。
- SCL 或 SDA 一直被拉低。
- 低速正常，高速异常。
- 一个设备正常，多个设备挂上后异常。

排查顺序：

1. 检查供电电压是否正确。
2. 检查 GND 是否共地。
3. 检查 SCL/SDA 是否接反。
4. 检查是否有上拉电阻。
5. 检查设备地址是否正确。
6. 检查 7 位地址和 8 位地址是否混用。
7. 降低 I2C 速率到 100 kHz 测试。
8. 用逻辑分析仪确认是否有 Start、Address、ACK。
9. 检查总线电平是否匹配，比如 3.3V 和 5V。
10. 检查是否有设备把 SDA 或 SCL 长时间拉低。

## 8. 第八阶段：深入主题

进阶内容：

- Clock Stretching：从机拉低 SCL 让主机等待。
- Multi-master：多主机仲裁。
- 10 位地址模式。
- SMBus 和 I2C 的区别。
- Fast-mode Plus 和 High-speed mode。
- 总线电容、上升时间和上拉电阻计算。
- 电平转换器在 I2C 中的使用。
- Linux 下的 I2C 设备模型和 `i2c-tools`。

## 9. 推荐学习顺序

建议按下面顺序推进：

1. 理解 I2C 是什么，以及 SCL/SDA 的作用。
2. 学会画 I2C 硬件连接图。
3. 理解上拉电阻和开漏输出。
4. 掌握 Start、Stop、ACK、NACK。
5. 掌握 7 位地址和读写位。
6. 学会读写寄存器。
7. 用开发板读取一个真实 I2C 器件。
8. 用逻辑分析仪看懂一次完整通信。
9. 根据芯片手册独立写一个简单驱动。
10. 学习常见故障排查和进阶特性。

## 10. 建议实验清单

入门实验：

- I2C 扫描器。
- 读取 OLED 或传感器的设备地址。
- 读取一个设备 ID 寄存器。

基础实验：

- 读取温湿度传感器。
- 读取 EEPROM 一个字节。
- 向 EEPROM 写入一个字节再读回。
- 配置一个传感器的工作模式。

进阶实验：

- 用逻辑分析仪分析 I2C 读写过程。
- 改变 I2C 速率观察通信变化。
- 改变上拉电阻观察波形变化。
- 手写软件模拟 I2C。
- 在 Linux 下使用 `i2cdetect`、`i2cget`、`i2cset`。

## 11. 阶段性检查

学到这里时，可以用这些问题检查自己：

- 为什么 I2C 空闲时 SCL 和 SDA 都是高电平？
- ACK 是谁发出的？
- 主机读数据时，数据是谁驱动到 SDA 上的？
- 为什么读寄存器前通常要先写寄存器地址？
- 0x68 和 0xD0 可能是什么关系？
- 没有上拉电阻时 I2C 会发生什么？
- 逻辑分析仪里看到 NACK，可能有哪些原因？
- 多个 I2C 设备为什么能共用两根线？

## 12. 一句话学习主线

先理解“两根线怎么连接多个设备”，再理解“时序怎么表示一次读写”，然后通过“读写寄存器”操作真实芯片，最后用“波形分析”解决实际问题。
