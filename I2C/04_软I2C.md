# 04 软 I2C

本文讲解软 I2C，也叫 GPIO 模拟 I2C、软件 I2C、Bit-Bang I2C。

软 I2C 的核心思想是：

> 不使用芯片内部 I2C 外设，而是用普通 GPIO 手动控制 SCL 和 SDA 的高低电平，按照 I2C 协议时序完成通信。

例如 STM32F103 的硬件 I2C1 常用 PB6/PB7：

```text
PB6 -> I2C1_SCL
PB7 -> I2C1_SDA
```

如果使用软 I2C，这两个引脚不一定非要用 PB6/PB7。只要是普通 GPIO，理论上都可以模拟：

```text
PB10 -> 软件 SCL
PB11 -> 软件 SDA
```

也可以用：

```text
PA8 -> 软件 SCL
PC9 -> 软件 SDA
```

具体取决于你的板子引脚连接。

## 1. 软 I2C 和硬件 I2C 的区别

硬件 I2C 是芯片内部有专门的 I2C 外设模块。

你调用库函数：

```c
I2C_GenerateSTART(I2C1, ENABLE);
I2C_Send7bitAddress(I2C1, addr, I2C_Direction_Transmitter);
I2C_SendData(I2C1, data);
```

真正的 START、地址发送、数据发送、ACK 检测，大部分由硬件 I2C 外设完成。

软 I2C 则是你自己控制 GPIO：

```c
SDA_LOW();
SCL_HIGH();
SCL_LOW();
SDA_HIGH();
```

每一个时钟、每一个数据位、每一次 ACK，都由代码手动产生。

对比：

| 项目 | 硬件 I2C | 软 I2C |
|---|---|---|
| 使用外设 | I2C 外设 | 普通 GPIO |
| 引脚限制 | 通常固定在复用引脚 | 几乎任意 GPIO |
| 时序产生 | 硬件产生 | 软件延时模拟 |
| 速度 | 更稳定，可以较快 | 受 CPU 和延时影响 |
| 代码复杂度 | 库函数较多，状态复杂 | 逻辑直观，但代码自己写 |
| 调试难度 | 硬件状态机有时不好排查 | 波形直观，容易用逻辑分析仪看 |
| CPU 占用 | 低 | 高 |

一句话：

> 硬件 I2C 更正规，软 I2C 更灵活。

实际学习和调试传感器时，软 I2C 很常用，因为它的时序完全由自己掌控，出了问题也更容易定位。

## 2. I2C 的两个信号线

I2C 只有两根线：

```text
SCL: 时钟线
SDA: 数据线
```

SCL 通常由主机产生。

SDA 用来传输数据，既可以由主机控制，也可以由从机控制。

例如写数据时：

```text
主机控制 SDA，主机发送数据给从机
```

读数据时：

```text
从机控制 SDA，从机发送数据给主机
```

ACK 阶段也很关键：

```text
主机发完 8 位数据后，要释放 SDA
从机在第 9 个时钟拉低 SDA，表示 ACK
```

所以 SDA 不是永远由主机控制。软 I2C 里面必须经常切换 SDA 的方向，或者使用开漏输出模拟“释放总线”。

## 3. 为什么 I2C 要用开漏

I2C 总线不是普通的推挽输出，而是开漏或开集电极结构。

它的电平规则是：

```text
谁都不拉低 -> 上拉电阻把线拉成高电平
任意一个设备拉低 -> 总线变成低电平
```

也就是说，I2C 设备一般只主动输出低电平，不主动强推高电平。

高电平来自外部上拉电阻。

典型连接：

```text
VCC
 |
[4.7k]
 |
SCL ---------------- MCU / Sensor / EEPROM

VCC
 |
[4.7k]
 |
SDA ---------------- MCU / Sensor / EEPROM
```

为什么这样设计？

因为 I2C 是多设备共用总线。如果一个设备输出高电平，另一个设备输出低电平，就会产生冲突。

开漏方式下，大家只做两件事：

```text
要输出 0: 拉低总线
要输出 1: 松开总线，让上拉电阻拉高
```

所以软 I2C 里常见的 `SDA_HIGH()` 不是“强制输出高电平”，更准确地说应该是：

```text
释放 SDA
```

## 4. 软 I2C 的 GPIO 配置

软 I2C 推荐把 SCL 和 SDA 配成开漏输出：

```text
GPIO_Mode_Out_OD
```

例如 STM32 标准库中：

```c
static void SoftI2C_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;

    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);
}
```

这里假设：

```text
PB10 -> SCL
PB11 -> SDA
```

最后一句：

```c
GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);
```

不是强推高电平，而是在开漏模式下释放 SCL 和 SDA。

如果外部有上拉电阻，总线就会变成高电平。

## 5. 最底层 GPIO 操作

为了让代码更清楚，一般会先写几个宏：

```c
#define SOFT_I2C_PORT GPIOB
#define SOFT_I2C_SCL  GPIO_Pin_10
#define SOFT_I2C_SDA  GPIO_Pin_11

#define SCL_HIGH() GPIO_SetBits(SOFT_I2C_PORT, SOFT_I2C_SCL)
#define SCL_LOW()  GPIO_ResetBits(SOFT_I2C_PORT, SOFT_I2C_SCL)

#define SDA_HIGH() GPIO_SetBits(SOFT_I2C_PORT, SOFT_I2C_SDA)
#define SDA_LOW()  GPIO_ResetBits(SOFT_I2C_PORT, SOFT_I2C_SDA)

#define SDA_READ() GPIO_ReadInputDataBit(SOFT_I2C_PORT, SOFT_I2C_SDA)
```

这里最容易误解的是：

```c
SDA_HIGH()
```

在开漏模式下，它更像是：

```text
释放 SDA
```

而不是强制把 SDA 推高。

所以可以这样理解：

```text
SDA_LOW()  -> 主动拉低 SDA
SDA_HIGH() -> 松手，等待上拉电阻拉高 SDA
```

SCL 也是类似：

```text
SCL_LOW()  -> 主动拉低 SCL
SCL_HIGH() -> 释放 SCL
```

大多数简单软 I2C 主机代码里，SCL 一般由主机控制。严格来说，有些从机可能会使用时钟拉伸，也就是从机拉低 SCL 让主机等待。简单驱动通常不处理这个特性。

## 6. 延时函数

软 I2C 需要人为制造时序间隔。

比如：

```c
static void SoftI2C_Delay(void)
{
    volatile uint16_t i;

    for (i = 0; i < 30; i++)
    {
    }
}
```

这个延时不是精确时间，只是粗略控制速度。

软 I2C 的速度由这个延时决定：

```text
延时越短 -> I2C 速度越快
延时越长 -> I2C 速度越慢
```

如果通信不稳定，可以先把延时调大。

常见 I2C 速度：

```text
标准模式: 100 kHz
快速模式: 400 kHz
```

软 I2C 初学阶段不建议追求速度，先保证波形正确。

## 7. START 信号

I2C 的 START 条件是：

```text
SCL 为高电平时，SDA 从高电平变成低电平
```

波形：

```text
SCL:  ----高--------
SDA:  ----高----低--
             ^
            START
```

代码：

```c
static void SoftI2C_Start(void)
{
    SDA_HIGH();
    SCL_HIGH();
    SoftI2C_Delay();

    SDA_LOW();
    SoftI2C_Delay();

    SCL_LOW();
    SoftI2C_Delay();
}
```

解释：

1. 先释放 SDA 和 SCL，让两根线都为高。
2. 在 SCL 高电平期间，把 SDA 拉低，产生 START。
3. 再拉低 SCL，为后面发送数据做准备。

START 是主机告诉所有从机：

```text
我要开始一次 I2C 通信了。
```

## 8. STOP 信号

I2C 的 STOP 条件是：

```text
SCL 为高电平时，SDA 从低电平变成高电平
```

波形：

```text
SCL:  ----高--------
SDA:  ----低----高--
             ^
            STOP
```

代码：

```c
static void SoftI2C_Stop(void)
{
    SDA_LOW();
    SoftI2C_Delay();

    SCL_HIGH();
    SoftI2C_Delay();

    SDA_HIGH();
    SoftI2C_Delay();
}
```

STOP 表示：

```text
本次 I2C 通信结束，总线释放。
```

## 9. 发送 1 个字节

I2C 发送数据时，规则是：

```text
高位先发，MSB first
```

也就是先发 bit7，再发 bit6，一直到 bit0。

每一位的基本流程：

```text
SCL 低电平时，改变 SDA
SCL 高电平时，从机读取 SDA
```

代码：

```c
static void SoftI2C_SendByte(uint8_t byte)
{
    uint8_t i;

    for (i = 0; i < 8; i++)
    {
        SCL_LOW();

        if (byte & 0x80)
        {
            SDA_HIGH();
        }
        else
        {
            SDA_LOW();
        }

        SoftI2C_Delay();

        SCL_HIGH();
        SoftI2C_Delay();

        byte <<= 1;
    }

    SCL_LOW();
}
```

关键点：

```c
if (byte & 0x80)
```

用来判断当前最高位是不是 1。

如果是 1：

```c
SDA_HIGH();
```

释放 SDA，让总线为高电平。

如果是 0：

```c
SDA_LOW();
```

主动拉低 SDA。

然后：

```c
SCL_HIGH();
```

产生一个高电平时钟，从机就在这个时间读取 SDA。

最后：

```c
byte <<= 1;
```

把下一位移动到 bit7 的位置，准备发送下一位。

## 10. 等待 ACK

I2C 每发送 8 位后，第 9 个时钟是 ACK 位。

规则：

```text
发送方发送完 8 位后，释放 SDA
接收方在第 9 个时钟期间拉低 SDA，表示 ACK
如果 SDA 保持高电平，表示 NACK
```

主机写数据给从机时：

```text
主机发送 8 位
主机释放 SDA
从机拉低 SDA 应答 ACK
```

代码：

```c
static uint8_t SoftI2C_WaitAck(void)
{
    uint8_t ack;

    SDA_HIGH();
    SoftI2C_Delay();

    SCL_HIGH();
    SoftI2C_Delay();

    if (SDA_READ() == Bit_RESET)
    {
        ack = 0;
    }
    else
    {
        ack = 1;
    }

    SCL_LOW();
    SoftI2C_Delay();

    return ack;
}
```

返回值可以这样约定：

```text
0: 收到 ACK，成功
1: 没收到 ACK，失败
```

最关键的是这句：

```c
SDA_HIGH();
```

主机发完 8 位后，必须释放 SDA。

否则如果主机还一直拉着 SDA，从机就没机会表达 ACK 或 NACK。

然后主机拉高 SCL：

```c
SCL_HIGH();
```

在第 9 个时钟期间读取 SDA：

```c
SDA_READ()
```

如果 SDA 被从机拉低，说明 ACK。

如果 SDA 还是高电平，说明 NACK。

## 11. 主机发送 ACK 和 NACK

读数据时，数据是从机发给主机。

主机收到 1 个字节后，也要给从机 ACK 或 NACK。

规则：

```text
主机拉低 SDA -> ACK，表示我还要继续读
主机释放 SDA -> NACK，表示我不读了
```

发送 ACK：

```c
static void SoftI2C_SendAck(void)
{
    SCL_LOW();
    SDA_LOW();
    SoftI2C_Delay();

    SCL_HIGH();
    SoftI2C_Delay();

    SCL_LOW();
    SDA_HIGH();
    SoftI2C_Delay();
}
```

发送 NACK：

```c
static void SoftI2C_SendNack(void)
{
    SCL_LOW();
    SDA_HIGH();
    SoftI2C_Delay();

    SCL_HIGH();
    SoftI2C_Delay();

    SCL_LOW();
    SoftI2C_Delay();
}
```

读多个字节时：

```text
前面的字节后面发 ACK
最后一个字节后面发 NACK
```

例如读 3 个字节：

```text
读 byte0 -> 主机 ACK
读 byte1 -> 主机 ACK
读 byte2 -> 主机 NACK
STOP
```

## 12. 读取 1 个字节

读 1 个字节时，SDA 由从机控制，主机只负责产生 SCL。

代码：

```c
static uint8_t SoftI2C_ReadByte(void)
{
    uint8_t i;
    uint8_t byte = 0;

    SDA_HIGH();

    for (i = 0; i < 8; i++)
    {
        byte <<= 1;

        SCL_LOW();
        SoftI2C_Delay();

        SCL_HIGH();
        SoftI2C_Delay();

        if (SDA_READ() == Bit_SET)
        {
            byte |= 0x01;
        }
    }

    SCL_LOW();

    return byte;
}
```

一开始：

```c
SDA_HIGH();
```

表示释放 SDA，让从机控制数据线。

然后主机每产生一个 SCL 高电平，就读取一次 SDA。

因为 I2C 是高位先传，所以每次先：

```c
byte <<= 1;
```

再根据 SDA 状态决定最低位是否置 1。

## 13. 写一个寄存器

常见从机寄存器写入流程：

```text
START
设备地址 + W
ACK
寄存器地址
ACK
数据
ACK
STOP
```

代码示例：

```c
uint8_t SoftI2C_WriteReg(uint8_t dev_addr, uint8_t reg_addr, uint8_t data)
{
    SoftI2C_Start();

    SoftI2C_SendByte(dev_addr);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 1;
    }

    SoftI2C_SendByte(reg_addr);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 2;
    }

    SoftI2C_SendByte(data);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 3;
    }

    SoftI2C_Stop();
    return 0;
}
```

注意这里的 `dev_addr` 通常传 8 位地址，也就是 7 位地址左移一位后的写地址：

```c
#define MPU6050_ADDR_WRITE  0xD0
#define MPU6050_ADDR_READ   0xD1
```

如果设备 7 位地址是 `0x68`：

```text
写地址: 0x68 << 1 | 0 = 0xD0
读地址: 0x68 << 1 | 1 = 0xD1
```

也可以在函数内部处理 R/W 位，但整个工程要统一，不要一会儿传 7 位地址，一会儿传 8 位地址。

## 14. 连续写多个寄存器

连续写流程：

```text
START
设备地址 + W
ACK
起始寄存器地址
ACK
data0
ACK
data1
ACK
data2
ACK
STOP
```

代码：

```c
uint8_t SoftI2C_WriteRegs(uint8_t dev_addr, uint8_t reg_addr, uint8_t *buf, uint8_t len)
{
    uint8_t i;

    if (len == 0)
    {
        return 1;
    }

    SoftI2C_Start();

    SoftI2C_SendByte(dev_addr);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 2;
    }

    SoftI2C_SendByte(reg_addr);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 3;
    }

    for (i = 0; i < len; i++)
    {
        SoftI2C_SendByte(buf[i]);
        if (SoftI2C_WaitAck())
        {
            SoftI2C_Stop();
            return 4;
        }
    }

    SoftI2C_Stop();
    return 0;
}
```

很多传感器支持寄存器地址自动递增，所以可以连续写。

但 EEPROM 这类器件通常还有页写入限制，例如一次最多写 8、16、32 或 64 字节，具体要看手册。

## 15. 读一个寄存器

读寄存器比写寄存器多一步重复 START。

流程：

```text
START
设备地址 + W
ACK
寄存器地址
ACK
RESTART
设备地址 + R
ACK
读取数据
NACK
STOP
```

代码：

```c
uint8_t SoftI2C_ReadReg(uint8_t dev_addr_write, uint8_t dev_addr_read, uint8_t reg_addr, uint8_t *data)
{
    SoftI2C_Start();

    SoftI2C_SendByte(dev_addr_write);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 1;
    }

    SoftI2C_SendByte(reg_addr);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 2;
    }

    SoftI2C_Start();

    SoftI2C_SendByte(dev_addr_read);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 3;
    }

    *data = SoftI2C_ReadByte();
    SoftI2C_SendNack();
    SoftI2C_Stop();

    return 0;
}
```

为什么读之前要先写寄存器地址？

因为从机内部有很多寄存器。主机要先告诉从机：

```text
我接下来要读哪个寄存器。
```

这个“告诉寄存器地址”的过程，是主机向从机写入一个寄存器地址，所以第一段是写方向。

真正读数据时，再通过重复 START 切换到读方向。

## 16. 连续读多个寄存器

连续读流程：

```text
START
设备地址 + W
ACK
起始寄存器地址
ACK
RESTART
设备地址 + R
ACK
读 data0
ACK
读 data1
ACK
...
读最后一个 data
NACK
STOP
```

代码：

```c
uint8_t SoftI2C_ReadRegs(uint8_t dev_addr_write, uint8_t dev_addr_read, uint8_t reg_addr, uint8_t *buf, uint8_t len)
{
    uint8_t i;

    if (len == 0)
    {
        return 1;
    }

    SoftI2C_Start();

    SoftI2C_SendByte(dev_addr_write);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 2;
    }

    SoftI2C_SendByte(reg_addr);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 3;
    }

    SoftI2C_Start();

    SoftI2C_SendByte(dev_addr_read);
    if (SoftI2C_WaitAck())
    {
        SoftI2C_Stop();
        return 4;
    }

    for (i = 0; i < len; i++)
    {
        buf[i] = SoftI2C_ReadByte();

        if (i == len - 1)
        {
            SoftI2C_SendNack();
        }
        else
        {
            SoftI2C_SendAck();
        }
    }

    SoftI2C_Stop();
    return 0;
}
```

关键点：

```c
if (i == len - 1)
{
    SoftI2C_SendNack();
}
else
{
    SoftI2C_SendAck();
}
```

主机读前面的字节后发送 ACK，表示继续读。

主机读最后一个字节后发送 NACK，表示读完了。

然后发送 STOP 结束通信。

## 18. 软 I2C 常见问题

### 18.1 没有上拉电阻

I2C 必须有上拉。

如果没有上拉，释放 SDA/SCL 后，线不一定能稳定变成高电平。

常见上拉电阻：

```text
4.7k
10k
2.2k
```

100 kHz 附近常用 4.7k 或 10k。

线长较长、设备较多、速度较快时，上拉可能要更强一些，也就是阻值更小。

### 18.2 SDA 没有释放

很多 ACK 失败都是因为主机发完 8 位后没有释放 SDA。

正确做法：

```c
SDA_HIGH();
SCL_HIGH();
ack = SDA_READ();
```

如果没有释放 SDA，从机无法拉低 SDA，主机就读不到正确 ACK。

### 18.3 地址传错

I2C 地址经常有 7 位地址和 8 位地址的区别。

例如设备手册写：

```text
7 位地址: 0x68
```

那么：

```text
写地址: 0xD0
读地址: 0xD1
```

如果你的软 I2C `SendByte()` 直接发送地址字节，那就传 `0xD0` 和 `0xD1`。

如果你的函数内部写成：

```c
SoftI2C_SendByte((dev_addr << 1) | 0);
SoftI2C_SendByte((dev_addr << 1) | 1);
```

那调用时就应该传 `0x68`。

这两种写法都可以，但不能混用。

### 18.4 延时太短

软 I2C 如果延时太短，波形可能不稳定。

表现可能是：

```text
偶尔读错
ACK 偶尔失败
读取到 0xFF
读取到 0x00
复位后第一次正常，后面异常
```

调试时可以先把延时加大，确认通信稳定后再慢慢优化速度。

### 18.5 GPIO 模式不对

推荐使用：

```text
开漏输出 + 外部上拉
```

如果用推挽输出，高电平时 MCU 会强推高。

当从机想拉低 SDA 发送 ACK 时，可能和 MCU 冲突。

### 18.6 STOP 后没有释放总线

STOP 后 SDA 和 SCL 应该都处于高电平。

如果 STOP 后还有线被拉低，说明总线没有释放，后续通信可能失败。

可以用逻辑分析仪或示波器检查：

```text
空闲状态: SCL = 1, SDA = 1
```

## 19. 软 I2C 和前面硬件 I2C 函数的对应关系

硬件 I2C 写法：

```c
I2C_GenerateSTART(I2C1, ENABLE);
I2C_WaitEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT);
I2C_Send7bitAddress(I2C1, addr, I2C_Direction_Transmitter);
I2C_WaitEvent(I2C1, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED);
I2C_SendData(I2C1, data);
I2C_WaitEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTED);
I2C_GenerateSTOP(I2C1, ENABLE);
```

软 I2C 写法：

```c
SoftI2C_Start();
SoftI2C_SendByte(addr_write);
SoftI2C_WaitAck();
SoftI2C_SendByte(data);
SoftI2C_WaitAck();
SoftI2C_Stop();
```

可以这样对应理解：

| 硬件 I2C | 软 I2C |
|---|---|
| I2C_GenerateSTART | SoftI2C_Start |
| I2C_Send7bitAddress | SoftI2C_SendByte 发送地址字节 |
| I2C_SendData | SoftI2C_SendByte |
| I2C_CheckEvent / I2C_WaitEvent | SoftI2C_WaitAck 或手动读 SDA |
| I2C_ReceiveData | SoftI2C_ReadByte |
| I2C_GenerateSTOP | SoftI2C_Stop |

硬件 I2C 的 `WaitEvent` 等的是外设内部状态位。

软 I2C 没有外设状态位，所以没有 `I2C_EVENT_MASTER_MODE_SELECT` 这种事件。软 I2C 等待的是实际引脚电平，例如 ACK 阶段读取 SDA。

## 20. 学习软 I2C 的重点

软 I2C 最重要的不是背代码，而是理解这几个点：

```text
START: SCL 高时 SDA 从高变低
STOP:  SCL 高时 SDA 从低变高
发送数据: SCL 低时改 SDA，SCL 高时对方采样
读取数据: 主机释放 SDA，拉高 SCL 后读取 SDA
ACK:    第 9 个时钟，接收方拉低 SDA
NACK:   第 9 个时钟，接收方不拉低 SDA
```

只要这几个时序理解清楚，软 I2C 的读写函数就不难。

一句话总结：

> 软 I2C 就是用 GPIO 手动模拟 I2C 时序。拉低表示 0，释放表示 1，靠 SCL 的高低变化让双方同步收发数据。
